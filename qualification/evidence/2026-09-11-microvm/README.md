# Bounded CPU/KVM proof — 2026-09-11

One temporary x86-64 host with nested KVM ran Firecracker 1.16.1 and guest Linux
6.1.155. KVM API version 12 and cgroup v2 CPU/memory/pids availability were observed.
The host kernel was 7.0.0-1012-aws. No cloud account, instance, IAM, bucket or network
identifiers are distributed in this evidence package.

The successful report and complete per-guest consoles are in `passed/`. The three
scripts in `../../microvm/` match `artifact-hashes.json`. The local OCI image and
export identity are described in that directory's reproduction instructions.
`evidence-hashes.json` detects accidental edits to the retained records; it is not
an external signature or authenticated provenance.

| Case | Observed outcome |
|---|---|
| Preparation | Fixed X circuit parsed and canonicalised in a fresh guest |
| Validation | Another guest reproduced the expected canonical/source/options observations |
| qpp sampling | Expected qubit-0-first counts `{"10":17}` |
| Requested kill | Waiting marker observed; supervisor killed VMM and observed PID gone |
| Excessive output | Supervisor killed VMM at the capture threshold; 131080 bytes retained |

All five guests reported UID 65532, only loopback, absent host canary/management
socket/AWS environment variables and unreachable metadata endpoints. Guest root
and inputs were configured read-only; no network interface was configured.
These synthetic probes are not a hostile escape test or proof of every kernel
isolation property. Effective cgroup exhaustion was not tested.

The first attempt reached init but failed because `/dev` was already mounted.
`first-attempt/` preserves that console/report: its 90-second deadline stopped the
VMM. The successful bootstrap accepts an already-mounted `/dev`. The supervisor
also now stops on bootstrap failure or successful completion, rather than relying
on guest poweroff to end the VMM. The preserved scripts are the successful versions;
the first-attempt report is historical failure evidence, not generated by them.

Successful guests also exit with supervisor SIGKILL after `QB_EXIT=0`; graceful
guest shutdown is not claimed. Termination evidence is the observed local VMM PID,
not a hosted cancellation receipt. Completion markers are a synthetic harness
protocol, not authority. The 131073-byte output threshold allows one 4096-byte read
chunk of overshoot. The stale-identity check is just a tuple comparison.

No GPU, Aer/noise, Integrations or Decoder matrix ran inside these VMs. Prior local
CPU container evidence remains separate. No durable supervisor restart/reconcile,
mutated-input scenario, authenticated preparation acceptance, result registration,
production attestation or customer execution was qualified. Matching parser output
is not independent proof of parser semantic correctness.

The operator verified the host terminated, its disk removed, the artifact bucket
empty and its termination schedule removed. The administrator then deleted the
foundation; its final deletion was verified. No ongoing test infrastructure remains.

## Scope review

The platform release owner reviewed the public package scope: preserve exact tested
scripts, failure history and honest exclusions; omit cloud identifiers and hosted
implementation. The CPU/KVM proof does not qualify Python/Fargate attestation or
permit issuing hosted receipt/schema identities. No platform or SDK change is part
of this package.
